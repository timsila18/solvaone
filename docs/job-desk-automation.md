# Job Desk automation

The Job Desk ingests permitted public job feeds. Admins may add a verified vacancy manually. Feed listings are cached once for all clients; closed listings are removed from matching after a successful refresh. Paid, readable CV intake queues preparation automatically. The admin reviews and approves the latest CV; that approval queues fresh discovery and matching. Suitable new matches queue tailored one-page cover letters, with OpenAI usage and estimated cost recorded in `job_desk_ai_runs`.

`job_desk_tasks` is a leased queue. `claim_job_desk_task` uses a row lock so only one worker can claim a task. A failed task is retried with backoff, up to three attempts. Supabase pg_cron calls the Vercel worker every five minutes using a token stored in Vault. The Vercel Hobby-compatible daily cron is a fallback; it is not sufficient alone for prompt queue processing. Check failed `process_cv` tasks and unreadable intake files before approving an order.

Every application requires an approved CV, recorded payment, client processing consent, and a prepared cover letter. New job-search intakes also record one explicit application authorization with a frozen snapshot of target roles, locations, work arrangement, and exclusions in `job_desk_orders.service_details.applicationScope`; the order-level flag is `application_authorized`. This is a separate checkbox on public intake, or a recorded WhatsApp authorization and evidence on admin intake. Merely receiving a CV is not authorization. Prepared matches inside that scope and above the automatic suitability threshold queue submission without repeated consent links. A legacy order remains on the prior per-vacancy link path until the admin records a one-time scope; out-of-scope matches still need a client exception approval. The order page can revoke automatic authorization. The worker rechecks the scope and order status immediately before sending.

Official ATS feeds provide discovery, not permission to submit applications through employer APIs. Such portal applications are marked `needs_human`. Only manually verified email-address vacancies can be sent automatically using Resend. `RESEND_API_KEY` and a verified `JOB_DESK_FROM_EMAIL` (falling back to `FROM_EMAIL`) must be configured for this adapter. The provider message ID is stored as the submission confirmation. A timeout or uncertain provider outcome pauses for review and is not silently retried. Per-vacancy exception links expire after seven days and are one-time use.

New job-hunting intakes require the client's email. The admin can correct the email on an existing order. CV review, CV approval, match preparation, application submission and human-action holds enqueue deduplicated `notify_client` tasks. The worker sends these updates to `job_desk_clients.email` from `JOB_DESK_FROM_EMAIL`; delivery attempts and failures remain visible in `job_desk_tasks`. Provider acceptance is not proof of inbox delivery. The client should also watch for employer replies directly, since employer applications set the client's address as Reply-To. Do not substitute an admin email when the client has not provided one.

The admin can view sources under `/dashboard/admin/job-desk/vacancies`, matches and actions on each order, and a client application report under each order's `report` route. For a portal application completed by a person, the admin records the employer confirmation before the report marks it submitted. Consent links can be sent manually over WhatsApp. No WhatsApp Business API or browser automation is assumed.

The admin review queue at `/dashboard/admin/job-desk/review` combines failed tasks, CV/client-information holds, portal application holds, and vacancies awaiting review. For an authorized portal application, the order page provides the official application link, approved CV and tailored letter downloads, and copyable client-confirmed answers. This is an assisted handoff, not automated portal submission: opening a link or copying answers does not change application status. The admin records only an actual employer confirmation. Suggested source boards include Kenya-focused official feeds; the admin connects them from the source catalogue. The Job Desk home page has a WhatsApp share link for the public client intake form; this does not read WhatsApp chats or attachments automatically.

When no verified email provider is configured, authorized email applications pause in `needs_human`. The admin order shows an employer-addressed Gmail draft plus downloadable approved CV and tailored cover-letter DOCX files. The admin sends the email and attachments from an account they control, then records the Gmail Message-ID. Opening the draft or downloading documents never changes the submission status. Only the recorded confirmation does. This fallback is manual, not automatic email delivery.

Operational checks: inspect `job_desk_tasks` for failed tasks, `job_desk_sources.last_error` for feed failures, `job_desk_applications` for `needs_human`, and Supabase cron run history for scheduler health. Use the admin controls to retry a failed feed or matching run after fixing the cause. Do not mark a portal application submitted without an external confirmation.
